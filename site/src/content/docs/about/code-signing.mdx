Code signing lets Windows show who published a program and that nobody has changed it since. This page explains how Keymotion's releases are built, signed and checked.

## Current status

Keymotion 0.1.0 is not code-signed yet, so Windows may warn you when you run the installer. [Installing Keymotion](/keymotion/guide/install/) shows how to continue.

The project is applying to SignPath Foundation for free code signing for open-source projects. When the project is accepted, its releases will be signed, and this page will carry SignPath's attribution.

## How releases are built

- Every release is built by GitHub Actions from the source code of its version tag, by the workflow in [`.github/workflows/release.yml`](https://github.com/cebersaban44-rgb/keymotion/blob/main/.github/workflows/release.yml). Release files are never built or uploaded from a personal computer.
- The workflow puts the release on GitHub as a draft. The maintainer reviews it and publishes it.
- The [release page](https://github.com/cebersaban44-rgb/keymotion/releases) lists the installer's SHA-256 checksum, so you can check that your download is the published file.

To compare the checksum:

<Steps>

1. Open the folder where you saved the installer, for example **Downloads**.
2. Right-click an empty space in the folder and choose **Open in Terminal**.
3. Type `Get-FileHash` followed by the installer's name, for example `Get-FileHash .\Keymotion_0.1.0_x64-setup.exe`, and press Enter.
4. Compare the long code it shows with the SHA-256 on the release page. They must be the same.

</Steps>

## How updates are checked

Each installer is also signed with Keymotion's own update key. The key has two halves:

- the private half stays secret with the project, and the release workflow uses it to sign each installer;
- the public half is built into Keymotion.

When Keymotion downloads an update, it checks the download against the public half. If the signature doesn't match, it doesn't install the update and says "The download couldn't be verified, so it wasn't installed." So Keymotion installs only updates signed with the project's key.

<Aside type="note" title="Not the same as Windows code signing">
The update key protects updates installed from inside Keymotion. It doesn't change the warning Windows may show when you run an installer you downloaded yourself.
</Aside>

## Signing requests

Once signing is set up, every signing request will be approved by hand by an approver before anything is signed.

## Privacy

Keymotion collects no usage data. It goes online only to read the calendars you add and to check GitHub for a new version. See the [privacy policy](/keymotion/about/privacy/).
