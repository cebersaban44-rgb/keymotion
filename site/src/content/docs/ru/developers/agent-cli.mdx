`keymotion-cli` позволяет скрипту или ИИ-агенту для программирования (Claude Code, Codex и другим, которые выполняют команды оболочки) сообщить пользователю что-то подсветкой клавиатуры: задача завершена, вопрос ждёт ответа, три теста не прошли. Что показать и как, решает агент; готовые сигналы — лишь сокращения, а клавиши, цвета, эффекты и время можно сочетать свободно.

<Aside type="caution">
Страница приложения, которая включает доступ для агентов и подключает Claude Code и Codex, уже готова (Инструменты › ИИ-агенты). Самого инструмента пока нет ни в установщике, ни в пакете Store; он появится на этапе упаковки. До тех пор его нужно собирать из репозитория (см. [Разработка](#разработка)).
</Aside>

## Как это работает

```text
agent ──runs──▶ keymotion-cli ──named pipe──▶ Keymotion (agent/) ──▶ device actor ──USB──▶ keyboard
```

- `keymotion-cli` никогда не открывает клавиатуру. Он отправляет запущенному приложению по одному JSON-сообщению на строку через именованный канал ([протокол 1](#именованный-канал), `crates/kb-agent`), а единственным владельцем клавиатуры остаётся актор устройства в приложении, со своими слоями подсветки и защитами. Тест следит за тем, чтобы стек HID, Tauri и tokio не попали в инструмент (`crates/keymotion-cli/tests/dependencies.rs`).
- Подсветка агентов — один слой подсветки в приложении: над таймером фокусировки, подсветкой игры, музыкальным режимом, системными показателями и профилем, выбранным по приложению; под предупреждениями, напоминаниями и их волнами ([Архитектура](/keymotion/developers/architecture/#from-a-click-to-a-hid-report)).
- Всё хранится только в оперативной памяти: в память клавиатуры ничего не записывается, и любая подсветка гаснет сама, самое позднее через 2 часа.
- Версия инструмента всегда совпадает с версией приложения (`version.workspace = true`); `keymotion-cli --version` выводит `keymotion-cli 1.2.0 (protocol 1)`.

## Команды

| Команда | Что делает | Запускает приложение |
|---|---|---|
| `status` | Запущен ли Keymotion, его версия и канал распространения, доступ для агентов и разрешения, клавиатуры и их подключение, видна ли сейчас подсветка агентов (а если нет, то почему: нет клавиатуры, нет USB-кабеля, игра, ночной режим), вся включённая сейчас подсветка агентов. Если приложение не запущено: `{"app":{"running":false}}` и код выхода 0. | Нет |
| `keys` | Идентификаторы и подписи клавиш клавиатуры, их положение в единицах клавиш и группы. | Да |
| `signal <name>` | Готовый сигнал: `done`, `attention`, `error`, `busy` или `info`. Вид каждого из них пользователь выбирает в приложении; `--color`, `--effect`, `--direction`, `--speed`, `--times`, `--for` и `--keys` переопределяют его для этого вызова. `busy` по умолчанию ничего не показывает и убирает прежние сигналы источника. | Да |
| `light` | Собственная подсветка агента: `--color` (обязательно), `--keys` (по умолчанию вся клавиатура), `--effect solid\|pulse\|blink\|flash\|wave`, `--direction left\|right\|up\|down` (для волны), `--speed 1-5`, а также `--times N` или `--for <duration>` (по умолчанию 60 с). | Да |
| `progress <percent>` | Полоса от 0 до 100 в ряду клавиш: ряд F или ряд цифр, по выбору пользователя, или `--keys`. `--label`, `--color`, `--for` (по умолчанию 10 минут после последнего обновления). Чтобы обновить полосу, отправьте команду снова с новым процентом. | Да |
| `clear` | Убирает одну подсветку (`--id`) или всю подсветку этого источника. Подсветку другого источника — никогда. | Да |
| `log` | Последние запросы агентов, которые приложение выполнило или отклонило (`--limit`, по умолчанию 20, не больше 200): источник, команда, результат, идентификатор и настройки, которые изменил запрос. | Да |
| `settings get [key]` | Настройки вида и поведения (вид сигналов, клавиши индикатора выполнения, ночной режим и остальное), а также какие ключи может менять только пользователь. | Да |
| `settings set <key> <value>` | Меняет одну настройку вида или поведения, например `signals.done.color green`. Пользователь видит это в «Последних действиях» приложения и может отменить. Доступ, разрешения, «Агенты могут менять эти настройки», «Скрывать подсветку агентов во время игры» и часовой лимит экрана меняет только пользователь: приложение отклоняет такие запросы (77). | Да |
| `version` | Версия и протокол инструмента, а если приложение запущено, то и его версия. О несовпадении протоколов сообщается, но ошибкой это не считается. | Нет |
| `guide` | Краткое руководство для агентов (не больше 60 строк): что выполнить сначала, идеи, значения, коды выхода. Агенты читают его, а не эту страницу. | Нет |
| `doctor` | Проверяет установку и завершается с кодом 0, что бы ни нашёл: инструмент; запущено ли приложение и отвечает ли оно; какая программа обслуживает канал (ожидается `keymotion.exe`) и принадлежит ли канал этому пользователю; версии и протокол; доступ для агентов; клавиатура и её USB-кабель; как инструмент запустил бы приложение; есть ли `keymotion-cli` в PATH или в папке псевдонимов Store; работает ли инструмент внутри контейнера пакета другого приложения. | Нет |
| `start` | Запускает приложение без окна и ждёт, пока оно ответит; если оно уже запущено, сообщает об этом. | Да |
| `connect claude-code\|codex` | Добавляет в настройки этого агента обработчики keymotion-cli, его навык и (для Codex) правило ([Агенты для программирования](#агенты-для-программирования-обработчики-и-навык)). Сначала говорит, что изменит; в терминале спрашивает, а в остальных случаях требует `--yes`. `--dry-run` только сообщает. | Нет |
| `disconnect claude-code\|codex` | Убирает только то, что добавил `connect`, и только созданные им пустые разделы. Те же `--yes` и `--dry-run`. | Нет |
| `connections` | Установлен ли и подключён ли каждый агент, а для Codex — доверили ли вы уже обработчикам. | Нет |
| `hook claude-code\|codex` | То, что агенты запускают на свои события: читает событие из stdin, ничего не выводит, всегда завершается с кодом 0 ([Режим обработчика](#режим-обработчика)). | Когда событие что-то подсвечивает |

Таймер фокусировки, профили, карточки на экране, сцены и слова по буквам на клавишах появятся на следующих этапах.

### Параметры для всех команд

| Параметр | Значение |
|---|---|
| `--json` | Ровно один JSON-объект в stdout, и при успехе, и при ошибке. То же задаёт `KEYMOTION_OUTPUT=json`. |
| `--source <name>` | Кто спрашивает (`claude-code`, `build-script`). У каждого источника своя подсветка, и убрать он может только свою. То же задаёт `KEYMOTION_SOURCE`; по умолчанию `cli`. До 64 символов из `a-z 0-9 : . _ -`. |
| `--timeout <duration>` | Сколько ждать приложение, вместе с подключением и ответом (по умолчанию `5s`, не больше `5m`). Если параметр задан, он ограничивает всю работу команды, включая запуск приложения, поэтому обработчик с ограничением по времени никогда не обрывается. Без него запуск приложения может занять до 15 секунд, а затем на сам вызов остаётся 5 секунд. |
| `--no-start` | Не запускать приложение; если оно не запущено, завершиться с кодом 69. |
| `-q`, `--quiet` | В текстовом режиме при успехе ничего не выводит ни в stdout, ни в stderr. Ошибки по-прежнему идут в stderr. |
| `--log <level>` | Диагностика в stderr: `off`, `error`, `warn` (по умолчанию; с `--quiet` — `error`), `info`, `debug`. |

### Значения

- **Клавиши:** идентификаторы из файла модели (`esc`, `f1`, `w`, `1`), нумерованные диапазоны (`f1-f12`, `1-3`), группы (`all`, `f-row`, `numbers`, `letters`, `wasd`, `arrows`, `numpad`), через запятую. Одни и те же имена работают на всех моделях; `keys` выводит их список.
- **Цвета:** `#RRGGBB`, `RRGGBB` или название: red, green, blue, amber, yellow, orange, purple, pink, cyan, white.
- **Длительности:** целое число и единица: `500ms`, `30s`, `5m`, `1h`; подсветка горит не дольше `2h`.
- **Идентификаторы:** без `--id` команда заменяет предыдущую подсветку источника того же вида (`<source>:light`, `<source>:progress`, `<source>:<signal>`). С идентификаторами у источника может быть до 8 подсветок; девятая вытесняет самую старую, и в ответе сказано, какую именно.
- Мигание и вспышки никогда не бывают чаще трёх раз в секунду (WCAG 2.3.1).

Инструмент проверяет значения до отправки тем же кодом, что и приложение (`kb-agent`), а приложение проверяет их ещё раз.

## Вывод

Результаты идут в stdout, диагностика — в stderr. Инструмент читает stdin только в режиме обработчика и задаёт вопрос только в `connect` и `disconnect`, когда запущен в терминале. Текстовый вывод — несколько коротких строк на английском. С `--json`:

```json
{"ok":true,"schema":1,"command":"signal","data":{"id":"claude-code:done","shown":true,"lit":true,"expires_in_ms":120000,"replaced":false,"evicted":[],"coalesced":false,"hidden":null},"warnings":[]}
```

```json
{"ok":false,"schema":1,"command":"light","error":{"code":"agent_access_off","message":"Agent access is off in Keymotion.","hint":"The user can turn it on in Keymotion › Tools › AI agents.","retry_after_ms":null}}
```

- `command` — команда в том виде, в каком её ввели (`signal`, `settings get`); `null`, если в командной строке не названо ни одной команды. `--help` и `--version` с `--json` отвечают как `help` и `version`, а текст находится в `data.text`.
- `data` — ответ приложения (для `version`, `guide`, `doctor`, `start` и `help` — собственный ответ инструмента). Для `signal`, `light` и `progress`: `id` подсветки, видна ли она сейчас (`shown`), `expires_in_ms`, заменила ли она прежнюю (`replaced`), что она вытеснила (`evicted`) и `hidden` (`"game"` или `"night"`), когда она ждёт.
- `warnings` — предложения для того, кто читает вывод: приложение было запущено ради этого вызова, подсветка пока перекрыта или скрыта, доступ для агентов выключен.
- `hint` и `retry_after_ms` равны `null`, когда их нет.
- `schema` остаётся равным 1, пока поля только добавляются; удаление поля или изменение его смысла увеличивает это число.
- Ничто из выводимого не может управлять терминалом. В текстовом выводе управляющие символы (включая escape-последовательности), а также невидимые символы и символы смены направления текста из ответов приложения или из повторённого ввода записываются явно (`\u{1B}`); в JSON символ DEL, управляющие символы C1 и эти символы превращаются в escape-последовательности `\u` в дополнение к тому, что JSON экранирует и так.

## Коды выхода

| Код | Значение | `error.code` |
|---|---|---|
| 0 | Выполнено | — |
| 1 | Что-то непредвиденное | `internal` |
| 64 | Командная строка: неизвестная команда или параметр, не хватает аргумента, несовместимые параметры | `bad_argument` |
| 65 | Значение: цвет, длительность, клавиша, эффект, идентификатор, число | `bad_color`, `bad_duration`, `bad_keys`, `unknown_key`, `bad_effect`, `bad_value`, … |
| 69 | Недоступно: приложение не запущено и запустить его не удалось, нет клавиатуры, нужен USB-кабель, канал принадлежит не Keymotion | `app_not_running`, `no_keyboard`, `needs_usb`, `unsupported`, `pipe_not_trusted` |
| 75 | Повторите позже: ограничение частоты (20 запросов в секунду на источник), истекло время ожидания, соединение закрылось | `rate_limited`, `timeout`, `connection_lost` |
| 76 | У инструмента и приложения нет общей версии протокола, приложение старше команды или сообщение нарушает протокол | `protocol_mismatch`, `unknown_command`, `bad_request`, `bad_response` |
| 77 | Не разрешено: доступ для агентов выключен или эту настройку может менять только пользователь | `agent_access_off`, `permission_off` |

Код выхода 2 никогда не используется: Claude Code и Codex понимают 2 от обработчика как «продолжай» (а Codex ещё и как «отклони разрешение»). Собственные ошибки использования clap превращаются в 64, а `--help` и `--version` завершаются с кодом 0.

## Запуск приложения

`status`, `version`, `guide` и `doctor` никогда не запускают приложение. Любая другая команда, если канал никто не обслуживает, запускает Keymotion без окна и ждёт появления его канала, если только не задан `--no-start`: до 15 секунд или, если задан `--timeout`, лишь столько, сколько он позволяет (`start` всегда ждёт 15 секунд). Если копия уже работает, но её канал ещё не открыт (она запускается), инструмент ничего не запускает и ждёт до 5 секунд; если это копия из Store, слишком старая, чтобы отвечать агентам, он сразу сообщает об этом.

Инструмент может работать внутри контейнера другого упакованного приложения: например, в терминале настольного приложения Claude. Программа, запущенная там как обычный дочерний процесс, остаётся в этом контейнере, поэтому её записи в AppData попадали бы в папку другого приложения, а читала бы она не настоящие настройки пользователя. API пакетов Windows такой контейнер не показывает (`GetCurrentPackageFullName` отвечает там «нет пакета»), но именованные каналы выходят за его пределы. Поэтому инструмент никогда не запускает `keymotion.exe` как свой дочерний процесс; он просит Windows запустить его, в таком порядке (`crates/keymotion-cli/src/launch.rs`):

1. Инструмент работает с удостоверением пакета Keymotion (через псевдоним выполнения приложения копии из Store): он активирует приложение пакета по его AUMID с `--background`.
2. Копия из Store установлена и достаточно новая: то же самое с AUMID пакета Store (правило «один Keymotion на компьютер» отдаёт предпочтение копии из Store). Достаточно новая — значит не старше первой версии, которая принимает `--background` (`kb_agent::BACKGROUND_START_SINCE`, 1.2.0), и не старше версии самого инструмента; версия читается из полного имени пакета. Более старая копия из Store открыла бы своё окно, и канала у неё нет, поэтому она никогда не запускается.
3. Схема адресов `keymotion:` открывает установленную копию с GitHub (её регистрирует именно она; регистрация сборки для разработки не считается: сделанная внутри контейнера другого приложения, она не видна Проводнику, и тот спросил бы пользователя, каким приложением открыть адрес): `explorer.exe keymotion://background` по полному пути Проводника, запускаемый через `CreateProcessW` без наследования дескрипторов (`kb_winsys::shell::run_alone`; собственный `Command` в Rust передаёт дальше все наследуемые дескрипторы), чтобы агент, читающий вывод инструмента, никогда не ждал Проводник. Копия с GitHub рядом со старой копией из Store тогда работает сама, скрыто, вместо того чтобы уступить место копии из Store.
4. Ничего из этого: сразу код выхода 69 и «start Keymotion» либо «update Keymotion from the Microsoft Store», если есть только старая копия из Store.

В приложении `--background` и `keymotion://background` означают «работать только со значком рядом с часами». Ни то ни другое не считается автозапуском вместе с Windows (для него по-прежнему `--hidden`), поэтому состояние окна и передача автозапуска между копиями не меняются. Запущенное приложение, получив любой из них, ничего видимого не делает, а копия с GitHub, которая уступает место копии из Store, передаёт ей `--background`, но только если копия из Store его знает (`app/src-tauri/src/tray.rs`, `handoff.rs`).

## Агенты для программирования: обработчики и навык

О том, что происходит, пользователю агента сообщают две вещи, и задачи у них разные. Пока агент ждёт подтверждения, он замер; когда отказывает его сервис, он вообще не работает; а сказать, что закончил, он может забыть. Эти моменты знает только само приложение для программирования, поэтому оно само и сообщает о них через **обработчики событий**: на свои события оно запускает `keymotion-cli hook <agent>`, а модель ничего об этом не знает и не тратит на это контекст. Когда сам агент хочет сказать что-то ещё (слово на клавишах, число, индикатор выполнения), он пользуется инструментом через **навык**: один короткий файл, в котором сказано, что инструмент есть и что сначала нужно выполнить `keymotion-cli guide`.

`keymotion-cli connect claude-code|codex` добавляет и то и другое; страница «ИИ-агенты» в приложении делает то же самое, когда вы включаете доступ для агентов, предварительно показав вам, что она добавит. Больше ничего в файлах агентов не затрагивается:

| | Claude Code | Codex |
|---|---|---|
| Папка настроек | `CLAUDE_CONFIG_DIR`, иначе `%USERPROFILE%\.claude` | `CODEX_HOME`, иначе `%USERPROFILE%\.codex` |
| Обработчики | `settings.json`, `hooks` | `hooks.json` |
| Как запускается обработчик | программа и её аргументы, без оболочки: `{"command": "<path>\\keymotion-cli.exe", "args": ["hook", "claude-code"]}` (Claude Code 2.1.139 или новее) | одна строка для его оболочки, PowerShell: `if (Test-Path -LiteralPath '<path>') { & '<path>' hook codex }` |
| Навык | `skills\keymotion\SKILL.md` | `%USERPROFILE%\.agents\skills\keymotion\SKILL.md` |
| Также | | `rules\keymotion.rules` (см. ниже) |
| Подтверждение | не нужно | Codex спрашивает один раз: `/hooks` или «Настройки › Хуки» в приложении |

- **Строка обработчика никогда не меняется.** Она одна и та же для всех событий и во всех версиях; что означает событие, определяют keymotion-cli и ваши настройки в Keymotion. Это важно для Codex, который просит снова доверить обработчику всякий раз, когда тот меняется. Строка называет keymotion-cli по пути, который не меняется: псевдоним выполнения приложения копии из Store (`%LOCALAPPDATA%\Microsoft\WindowsApps\keymotion-cli.exe`, но никогда не папка пакета с номером версии), папка `bin` копии с GitHub или собственный путь сборки для разработки (с предупреждением: если сборку переместить, обработчики перестанут работать).
- **Почему две формы.** Claude Code запускает `command` обработчика через Git Bash, если он установлен, а иначе через PowerShell, и не существует записи пути в кавычках с аргументами после него, которую обе оболочки поняли бы одинаково (PowerShell отклоняет путь в кавычках, за которым идут слова; в Bash `&` запускает фоновое задание). Форма `args` запускает саму программу, поэтому пробелы в папке пользователя не мешают. Codex 0.166.0 запускает каждый обработчик через `powershell -NoProfile -Command`. Путь заключается в кавычки для PowerShell, и каждый из пяти символов, на которых PowerShell заканчивает строку в кавычках (`'` и типографские `‘ ’ ‚ ‛`), удваивается, так что работает и папка вроде `O’Brien`. Сначала строка проверяет, что программа на месте: после удаления Keymotion обработчики Codex ничего не делают и ничего не сообщают. Путь, который PowerShell проверить не может (одно только имя), вместо этого ищется через `Get-Command`.
- **Claude Code 2.1.139 или новее.** Форма `args` появилась в 2.1.139; более старый Claude Code запустил бы программу без `hook claude-code`. До 2.1.101 неизвестное ему событие обработчика заставляло его игнорировать весь файл настроек. Поэтому `connect` отказывается работать с найденным более старым Claude Code (`claude.exe` в `%USERPROFILE%\.local\bin` или пакет npm) и предлагает его обновить; `connections` предупреждает о том же. Режим обработчика этого никогда не проверяет (чтобы оставаться быстрым).
- **Ваши файлы остаются вашими.** Только строгий JSON: файл, который не удаётся прочитать, отклоняется и остаётся как есть. Ваши ключи и обработчики сохраняют свой порядок, а файл — свои отступы и концы строк; наши записи идут отдельными группами, в самом конце. Перед каждым изменением сохраняется копия файла в прежнем виде (`settings.json.before-keymotion`). Файлы записываются целиком через временный файл, который сбрасывается на диск, прежде чем занять место файла; если файл — ссылка, запись идёт туда, куда она указывает, а ссылка остаётся. Каждый файл перечитывается непосредственно перед записью: если агент изменил его после того, как keymotion-cli сказал, что изменит (например, пока вы решали), план строится заново по текущему состоянию файла, а в терминале вопрос задаётся снова; из старой копии файл никогда не записывается. Файл правил или навык, который не принадлежит Keymotion, отклоняется. Повторное подключение ничего не меняет; подключение из другой копии keymotion-cli обновляет наши записи на месте. `connection.json` рядом с навыком запоминает, что было создано при подключении, поэтому отключение удаляет только это.
- **Правило Codex.** Codex выполняет команды агента в песочнице, из которой недоступен именованный канал Keymotion, созданный для конкретного пользователя. `rules\keymotion.rules` позволяет `keymotion-cli status|keys|signal|light|progress|clear|log|settings|version|guide|doctor|start` выполняться вне песочницы без вопросов — по имени или по полному пути этого keymotion-cli (`host_executable`), но не любой другой программе с тем же именем: копия, которую принёс с собой репозиторий, остаётся в песочнице. `connect`, `disconnect` и `hook` в правило не входят. Проверено с помощью `codex execpolicy check --resolve-host-executables`.
- **Навык** одинаков для обоих агентов и остаётся кратким: инструмент есть, сначала выполните `keymotion-cli guide` (а если `keymotion-cli` не найден, то по полному пути), как сообщать что-то пользователю, решаете вы, а готовые сигналы необязательны. В нём есть отметка версии; при запуске приложение перезаписывает собственный файл навыка и правило Codex, если они старше его версии, — только их, только там, где они находятся, и называя тот же keymotion-cli, который они называли.

`keymotion-cli connections --json` сообщает для каждого агента `state`: `not_found`, `not_connected`, `connected`, `needs_approval` (Codex: обработчики, которым вы ещё не доверили; читается из `config.toml` Codex, в который keymotion-cli никогда не пишет), `outdated` (каких-то наших записей не хватает или они называют другой keymotion-cli) или `unreadable`; а также `warning`, если найденный Claude Code слишком старый.

### Страница «ИИ-агенты»

Приложение делает то же самое через `kb_hooks::setup` (`app/src-tauri/src/agent/apps.rs`), с такими командами Tauri для своей страницы Инструменты › ИИ-агенты:

| Команда | Что делает |
|---|---|
| `agents_connections` | Claude Code и Codex: есть ли они на этом компьютере, их состояние (как выше, а также `tooOld` с найденной версией и `minVersion` 2.1.139 для Claude Code), keymotion-cli, который поставляется с этой копией, и на месте ли он, а для копии с GitHub — есть ли её папка `bin` в PATH. |
| `agents_connect_plan { apps? }` | Что добавит включение доступа для агентов в каждое найденное приложение для программирования: каждый файл — создаётся, меняется или удаляется, что это (обработчики и сколько их, навык, правило Codex, собственная заметка Keymotion), где хранится его копия; попросит ли Codex доверить обработчикам; почему приложение нельзя подключить (`problem`). Ничего не записывается. `token` обозначает то, что было показано. |
| `agents_connect { token, apps? }` | Пользователь подтвердил: приложения подключаются, папка `bin` добавляется в PATH (копия с GitHub), и доступ для агентов включается (если только не все приложения завершились неудачей). Если приложение для программирования тем временем записало свои настройки, план строится заново: если он показывает то же самое, он записывается с сохранением новых записей приложения; если нет, ничего не меняется и возвращается новый план (`applied: false`), чтобы показать его снова. При двойном подтверждении (двойной щелчок) второе находит всё уже сделанным и завершается успешно. Приложение, которое не удалось подключить, не останавливает остальные, а приложению, не все файлы которого удалось записать, возвращается то, что было (`problem: partial`, если не удаётся даже это: тогда отключение удаляет то, что осталось). |
| `agents_disconnect_plan { app }`, `agents_disconnect { app }` | Что удалит отключение, и само отключение. Доступ для агентов и PATH остаются как есть. |

**PATH (копия с GitHub).** Включение доступа для агентов в приложении также добавляет папку `bin` установки, где лежит `keymotion-cli.exe`, в конец вашего собственного PATH (`HKCU\Environment`) и сообщает об этом открытым программам; терминалы, открытые после этого, находят `keymotion-cli` по имени. Само по себе это никогда не происходит, и только если `keymotion-cli.exe` на месте. Значение читается и записывается обратно точно тем же текстом, с тем же типом (`REG_EXPAND_SZ` таким и остаётся), а всё остальное в нём не меняется и не переставляется; PATH, который не удаётся прочитать (другой тип, отказано в доступе), никогда не записывается, и страница объясняет почему. Перед изменением прежнее значение сохраняется в `HKCU\Software\Keymotion\UserPath` (`PathBefore`) вместе с папкой, которую добавил Keymotion (`PathAdded`). Папки сравниваются так же, как Windows сравнивает имена (порядково, без учёта регистра); папка с `;` в имени заключается в кавычки. Выключение доступа её оставляет; удаление программы её убирает, но только если её добавил Keymotion (папка, которую вы добавили сами, остаётся); обновления её не трогают. Копии из Store ничего из этого не нужно: её псевдоним лежит в папке, которую Windows держит в PATH.

**Перед удалением Keymotion** отключите приложения (в Keymotion кнопкой «Отключить» или командами `keymotion-cli disconnect claude-code` и `disconnect codex`). Обработчики Claude Code называют саму программу и не могут проверить, на месте ли она: после удаления Keymotion Claude Code сообщает о сбое обработчика при каждом событии, пока их не удалят. Строка Codex сначала проверяет и ничего не делает.

### Режим обработчика

`keymotion-cli hook claude-code|codex` читает событие из stdin (не больше 16 МиБ, в течение 2 секунд и вовсе не читает, если это терминал) и отправляет приложению один запрос `hook` с тем, что означает событие. Затем завершается.

- **Всегда 0 и ни байта в stdout**, что бы ни пришло: некорректный JSON, неизвестное событие или агент, нет приложения, доступ для агентов выключен, паника. Код выхода 2 означает для этих агентов «отклони разрешение», «продолжай» или «заблокируй сообщение», а текст в stdout Codex понимает как решение. Этот режим распознаётся до разбора командной строки, поэтому никакая ошибка в его командной строке не может привести и к коду 64.
- **Быстро.** Один короткий запрос к приложению (около 12–15 мс в выпускной сборке, включая запуск процесса); агент может его ждать. Если приложение не запущено, обработчик его не ждёт (см. ниже).
- **Из процесса уходит только смысл.** Считываются: имя события, идентификатор сеанса (он превращается в источник вроде `claude-code:3f9a0c1d`, хеш), последняя папка рабочего каталога (показывается рядом с номером сеанса), тип уведомления, вид сбоя, тип вспомогательного агента. Никогда не отправляются и не записываются в журнал: сообщение пользователя, сообщения агента, путь к файлу переписки, ввод и вывод любых инструментов. Вызов инструмента обозначается только его хешем с солью сеанса, чтобы вопрос можно было сопоставить с ответом на него.
- `KEYMOTION_HOOK_LOG=1` выводит в stderr, что сделал режим обработчика (смысл события и ответ приложения); агенты не показывают stderr обработчика, если он завершился с кодом 0.

#### Когда Keymotion не запущен

- **Событие, которое что-то подсвечивает** (ждёт вашего подтверждения, готово, ошибка, достигнут лимит использования), запускает Keymotion. Обработчик передаёт его копии keymotion-cli, которая работает сама по себе: без дескрипторов, без окна, вне объекта задания того, кто запускает обработчики, если тот это позволяет, в папке Windows, а не в папке проекта агента, а в копии из Store — через псевдоним выполнения приложения, который запускает её с пакетом Keymotion. Эта копия запускает Keymotion так же, как `start`, и доставляет событие.
- **Только одна такая копия за раз** (именованный мьютекс и собственный именованный канал рядом с каналом Keymotion). Обработчики, которые приходят, пока Keymotion запускается, — в том числе ответы и новые сообщения — по порядку встают в очередь за первым событием; когда Keymotion отвечает, очередь передаётся ему без того, что устарело из-за пришедшего позже (вопрос, на который тем временем ответили, «готово» перед новым сообщением), и без всего, что старше минуты. Затем копия ещё две секунды передаёт то, что приходит, и завершается.
- **Не стоит запуска Keymotion:** новое сообщение, ответ, начало или конец сеанса, завершение вспомогательного агента (H).
- **Если вы закрыли Keymotion, он остаётся закрытым.** Когда вы закрываете Keymotion командой «Выйти» в его меню или выключаете доступ для агентов, он записывает заметку `stopped.json` в папку навыка каждого подключённого агента, и пока она там, обработчики ничего не запускают. Keymotion удаляет её, когда запускается с включённым доступом и когда доступ включают. Закрытие действует только до конца текущего входа в систему: после перезапуска Windows или повторного входа первое событие запускает Keymotion, как раньше. Завершение работы Windows или выход из системы закрытием Keymotion не считаются. Если заметки нет или её не удаётся прочитать, значит, Keymotion просто не запущен. Собственные команды агента (`keymotion-cli signal …`) по-прежнему его запускают.
- **Почему папка навыка.** Обработчик может работать внутри контейнера другого упакованного приложения (настольное приложение Claude запускает Claude Code в своём). Такой контейнер видит собственную копию `%LOCALAPPDATA%` и `%APPDATA%`, поэтому заметка, которую Keymotion записал бы туда, не дошла бы до обработчика в контейнере; остальная часть папки пользователя общая для всех (проверено с настольным приложением Claude 23 ноября 2026 года). Папки навыков находятся именно там и существуют ровно тогда, когда агент подключён.

Что означают события (сверено с документацией агентов, а для Codex — с его исходным кодом версии 0.166.0):

| Значение | Claude Code | Codex |
|---|---|---|
| Начинается сеанс: он получает свой номер | `SessionStart` | `SessionStart` |
| Работает: прежняя подсветка сеанса гаснет | `UserPromptSubmit` | `UserPromptSubmit` |
| Вы остановили ход: его вопрос и подсветка «работает» гаснут, то, что было до него, остаётся | | `Interrupt` |
| Ждёт вашего подтверждения (`attention`) | `PermissionRequest`; `PreToolUse` для `AskUserQuestion` и `ExitPlanMode`; `Elicitation`; `Notification` `permission_prompt`, `elicitation_dialog`, `elicitation_url_dialog`, `agent_needs_input` | `PermissionRequest` |
| Ответ получен | `PostToolUse`, `PostToolUseFailure`, `PermissionDenied` (этот вызов); `PostToolBatch`, `ElicitationResult`, `Notification` `elicitation_complete`, `elicitation_response` (все вызовы сеанса) | `PostToolUse` (этот вызов), `PreModelRequest` (все вызовы этого хода) |
| Готово | `Stop` | `Stop` |
| Ошибка | `StopFailure` | `PostModelRequest` с `status: failed` |
| Достигнут лимит использования (A) | `StopFailure` с `rate_limit`, `billing_error`, `server_error` (перегруженный сервис) | неудачный запрос, сообщение которого говорит о лимите использования или частоты, кредитах, лимите расходов, квоте или модели, исчерпавшей свои мощности, либо который прекратил повторные попытки при статусе 429 или 5xx (`exceeded retry limit, last status: 429`) |
| Вспомогательный агент закончил (H) | `SubagentStop` (с типом), `TaskCompleted` | `SubagentStop` |
| Сеанс завершается | `SessionEnd` | `SessionEnd` |

- **«Ждёт вашего подтверждения» горит, пока вы не ответите**, но не дольше своей длительности (по умолчанию 30 минут), если так задано в его виде (`signals.attention.until_answered`, по умолчанию включено); конец хода в любом случае его гасит. Keymotion отслеживает вызовы инструментов, ответа на которые он ждёт: если одновременно выполняется несколько вызовов, завершение другого вызова подсветку не гасит, а ответ на последний — гасит. Вопрос без собственного вызова (форма, вопрос из уведомления) гаснет только от ответа на уровне всего сеанса: завершение вызова вспомогательного агента ответом на него не считается. Подтверждённый вызов заканчивается своим `PostToolUse`, поэтому долгая команда, которую вы подтвердили, держит подсветку, пока не завершится (ни один из агентов не сообщает, когда вы подтверждаете).
- **Нажатие клавиши гасит её.** Когда вопрос уже показан на клавишах (его первые вспышки закончились — это около секунды — и закончилась вспышка, отмечающая ваше возвращение к компьютеру), первое касание клавиатуры или мыши гасит подсветку: вы её видели. Ввод до этого или пока подсветку не видно (её скрывает игра, её выключил ночной режим, нет кабеля) не считается. Вопрос по-прежнему открыт: через пять минут он не мигает снова, подкрепляющее его уведомление не зажигает его снова, а если сеансов два или больше, клавиша с его номером горит ровным светом, пока на вопрос не ответят. Новый вопрос снова зажигает подсветку.
- **`idle_prompt` Claude Code** (примерно через минуту после каждого завершённого хода) ничего не подсвечивает: «готово» этого хода уже сказало об этом, а «ждёт вашего подтверждения» после каждого хода обесценило бы сигнал.
- **Codex** повторяет некоторые неудачные запросы; повторная ошибка того же хода оставляет подсветку как есть, а успешный запрос этого хода её гасит. Неудачный ход заканчивается без `Stop`.
- **Конец сеанса** убирает его вопрос и его номер; то, чем он закончился (готово, ошибка), остаётся на своё время, поскольку неинтерактивный запуск (`claude -p`, `codex exec`) завершает сеанс сразу после своего хода.
- **B, «Какой сеанс ждёт».** Каждый сеанс получает наименьший свободный номер от 1 до 9, когда впервые обращается к Keymotion. Сеанс учитывается, если о нём было слышно в последние 30 минут или его вопрос сейчас на клавишах; сеанс, молчавший дольше, отдаёт свой номер новому сеансу, которому номер нужен, а завершившийся сеанс возвращает номер сразу (сеанс, о котором ничего не слышно 12 часов, забывается). Если таких сеансов два или больше, клавиша с номером ждущего сеанса горит белым поверх подсветки «ждёт»; `status` и раздел «Номера сеансов» на странице «ИИ-агенты» показывают номер, папку проекта и агента.
- **A, H** и вид сигналов — это ваши настройки в Keymotion (`usage_limit.*`, `helper.*`, `sessions.*`); H по умолчанию выключено.

Обработчики, которые добавляет Keymotion: для Claude Code — `SessionStart`, `UserPromptSubmit`, `PreToolUse` (сопоставитель `AskUserQuestion|ExitPlanMode`), `PermissionRequest`, `PermissionDenied`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `Notification`, `Elicitation`, `ElicitationResult`, `Stop`, `StopFailure`, `SubagentStop`, `TaskCompleted` и `SessionEnd` (ограничение по времени 10 с; 2 с для `SessionEnd`, чьё ограничение распространяется и на ваши собственные обработчики `SessionEnd`; события вызовов инструментов выполняются без ожидания со стороны Claude Code); для Codex — `SessionStart`, `UserPromptSubmit`, `PermissionRequest`, `PostToolUse`, `PreModelRequest`, `PostModelRequest`, `Stop`, `Interrupt`, `SubagentStop` и `SessionEnd` (Codex запускает PowerShell для каждого обработчика, это около секунды на тестовом компьютере, поэтому он ждёт только `Interrupt` и `SessionEnd`, которые ждёт всегда, не дольше 3 с).

## Безопасность

- **Этот компьютер, этот пользователь.** Канал называется `\\.\pipe\keymotion-agent-<user SID>-<session>`, отклоняет сетевых клиентов, а его дескриптор безопасности допускает только пользователя, который запустил приложение. Приложение создаёт канал как первый экземпляр, поэтому другая программа не может незаметно занять это имя заранее; инструмент отклоняет канал, который не принадлежит этому пользователю, прежде чем отправить хоть один байт, а `doctor` называет процесс, который канал обслуживает. Нет ни прослушивателя TCP или HTTP, ни файла с токеном.
- **Переключатель пользователя.** Доступ для агентов выключен, пока пользователь не включит его в приложении («Агенты могут пользоваться клавиатурой»); пока он выключен, отвечают только `status`, `keys`, `log` и `settings get`, а остальные команды завершаются с кодом 77. Ни одна команда не может включить доступ или какое-либо разрешение.
- **Ограничения, которые защищают клавиатуру и пользователя.** Только оперативная память; 20 запросов в секунду и 8 подсветок на источник; не больше 3 вспышек в секунду; не больше 2 часов на подсветку; предупреждение о выключенном микрофоне и напоминание о встрече всегда показываются поверх подсветки агентов; игра, которая просит не трогать клавиатуру, скрывает её (пользователь может это выключить).
- **Источники разделены.** Источник не может убрать или заменить подсветку другого источника.
- **Ничего личного не записывается в журнал.** Приложение записывает источник, команду и результат каждого запроса. Режим обработчика отправляет только смысл события ([Режим обработчика](#режим-обработчика)).
- **Настройки других программ — только по запросу.** `connect` и `disconnect` меняют файлы Claude Code и Codex только по вашей просьбе, сначала сказав, что изменится, и только собственные записи Keymotion; правило Codex выпускает из песочницы только команды подсветки и состояния.

## Именованный канал

Протокол 1 описан в `crates/kb-agent/src/protocol.rs`: JSON с разделением по строкам, не больше 64 КиБ на строку, первым идёт `hello` с версиями протокола, которые поддерживает каждая сторона. Инструмент представляется в `hello` как `keymotion-cli` со своей версией и отклоняет приложение, которое выбирает версию, которую он не поддерживает (76). Соединение, которое приложение закрыло из-за простоя, открывается заново один раз, в пределах того же срока.

## Разработка

```bash
cargo build -p keymotion -j 2          # the app (start it, or the dev server's build)
cargo run -p keymotion-cli -- status
cargo run -p keymotion-cli -- light --keys f1-f12 --color green --effect wave --times 1
cargo test -p keymotion-cli
```

Прежде чем пробовать команды, которым нужно приложение, запустите сборку приложения для разработки: если не запущен ни один Keymotion, инструмент запускает установленный (копию из Store, если она достаточно новая). `--no-start` не даёт ему ничего запускать.

Пробуйте `connect` на тестовой папке и никогда — на настройках Claude Code или Codex, с которыми вы работаете: `KEYMOTION_CLI_TEST_HOME=<folder>` заставляет `connect`, `disconnect` и `connections` работать в `<folder>\.claude`, `<folder>\.codex` и `<folder>\.agents` (`CLAUDE_CONFIG_DIR` и `CODEX_HOME` учитываются, только если указывают внутрь неё). Сборка приложения для разработки, запущенная с сервером разработки, читает ту же переменную для своей страницы «ИИ-агенты» (и для заметок, которые она оставляет рядом с навыком), так что страницу можно попробовать, не трогая собственные настройки; PATH она тогда не трогает. Установленная копия, включая собранную через `tauri build --debug`, эту переменную никогда не читает. Записанное событие подаётся вручную:

```powershell
'{"hook_event_name":"Stop","session_id":"s1","cwd":"C:\\dev\\demo"}' | cargo run -p keymotion-cli -- hook claude-code
```

Тесты запускают настоящую программу `keymotion-cli` против поддельного приложения, построенного на `kb_agent::transport::serve`, на собственном канале (`KEYMOTION_CLI_TEST_PIPE`, который также заменяет запуск приложения пустой операцией). Эту переменную читают только отладочные сборки и сборки с функцией Cargo `test-pipe`; выпускная сборка — никогда, поэтому тот, кто задаёт переменные окружения, не может направить вызовы агентов в поддельное приложение. Интеграционные тесты собираются только там, где она читается (`cargo test --release --features test-pipe` для прогона в выпускной сборке). Проверены все команды, выключенный доступ, отсутствие приложения, зависшее приложение, другой протокол и все ошибки использования, и ни один прогон не может завершиться с кодом 2. `tests/hooks.rs` подаёт режиму обработчика мусор, пустой ввод, 17 МиБ и неизвестных агентов (каждый раз 0 и никакого вывода), проверяет, что доходит до приложения, доставляет событие приложению, которое запускается позже, а также подключает и отключает агентов в тестовой домашней папке внутри папки с пробелами в имени, после чего выполняет строки обработчиков, записанные `connect`, так же, как это делают агенты: строку Claude Code — как программу с аргументами, строку Codex — через PowerShell (а простую строку — ещё и через `cmd.exe`). `KEYMOTION_CLI_TEST_HOME` читают те же сборки, что и тестовый канал.
