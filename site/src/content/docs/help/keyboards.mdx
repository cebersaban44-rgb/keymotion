Keymotion works with the **AJAZZ AK980 PRO**. Many keyboards are built on the same platform: the same kind of chip, the same command set and often the same vendor program, sold under different names. They could come next, but each one is added only after someone has tried it, because the details that keep a keyboard safe differ from model to model.

## Tested and working

<Image src={ak980} alt="AJAZZ AK980 PRO" width={520} />

| Keyboard | USB cable | 2.4 GHz receiver | Bluetooth | Status |
|---|---|---|---|---|
| **AJAZZ AK980 PRO** | Everything | Typing, media keys and the knob | Typing, media keys, the knob and the battery level | <span class="km-status" data-s="works">Works · tested</span> |

Shops sell this keyboard under more than one name. The one Keymotion is tested with came from AJAZZ's own store, listed as "AK980MAX … V2", with **AK980 V2** on the box. Over USB it gives SONiX as its maker and "AK980 PRO" as its name, and Keymotion recognizes it by that name. So the **AJAZZ AK980 V2** with the screen works too. Other AK980 versions, for example ones without the screen, may be different inside. Keymotion takes a keyboard for this one only if it gives that name and, when Keymotion checks it on connecting, is built the same way inside. Otherwise Keymotion sends nothing to it and offers **Request support** instead.

Keymotion is tested with the keyboard's firmware 1.06; on another version it asks you before it saves anything to the keyboard. AJAZZ's newest firmware, 3.01, uses a different set of commands; Keymotion supports it in beta, as described [below](#ak980-pro-on-firmware-301-beta).

Settings travel over the USB cable; that is how the keyboard is built. [Connecting the keyboard](/keymotion/guide/connecting/) explains the three connections.

## AK980 PRO on firmware 3.01 (beta)

AJAZZ's newest firmware for the AK980 PRO, 3.01 ("AK980 Led v2 Firmware 769"), switches the keyboard to a different set of commands. Keymotion supports it in beta, over the USB cable. To see which firmware your keyboard has, connect the cable and open **Connection**: the keyboard's details show it next to **Firmware**. On firmware 3.01, the **Overview** and the **Connection** page mark it **In beta**.

| Connection | What Keymotion does with firmware 3.01 |
|---|---|
| USB cable | Lighting effects and per-key color, live lighting, key mapping on both layers, macros, pictures on the screen, the clock and the battery level |
| 2.4 GHz receiver | Nothing new: it sends nothing over the receiver, as with the older firmware |
| Bluetooth | As before: it reads the battery level |

Beta means that this support is new and still being tested. So Keymotion is extra careful with it:

- Before it can write anything, it saves a backup of the keyboard's settings, which it can put back later.
- It asks you before it first writes to the keyboard, as it does on any firmware it hasn't been tested with.
- It reads back every setting it saves (key mapping, lighting, macros) to check it. The keyboard ignores writes for a moment after it starts up or is reset, so Keymotion waits before its first write.
- If what the keyboard reports doesn't look as expected, Keymotion writes nothing to the keyboard and says why at the top of the page; see [If something goes wrong](/keymotion/help/recovery/#when-keymotion-writes-nothing-to-the-keyboard). A keyboard without per-key colors, as after a firmware update (or a reset from AJAZZ's web tool), is normal and doesn't stop it.

A few things work differently on this firmware: an upload to the screen may replace the keyboard's clock page, the battery level shows over the cable too, the Key mapping and Macros pages show what is on the keyboard itself, and a few key choices aren't offered. [Should I install AJAZZ's newest firmware?](/keymotion/help/faq/#should-i-install-ajazzs-newest-firmware) goes through them.

Have you tried it? The [test guide](#the-test-guide) below takes you through it step by step; or [tell us how it works](https://github.com/cebersaban44-rgb/keymotion/issues/new?template=keyboard.yml&title=%5BKeyboard%5D+AJAZZ+AK980+PRO+firmware+3.01&model=AJAZZ+AK980+PRO+firmware+3.01) in your own words. If something goes wrong, send a report from **Settings**: under **About**, next to **Feedback**, click **Report a problem**. The report includes what Keymotion read about the keyboard, never your macros' contents; for a part that doesn't look as expected, it includes its first and last bytes.

An AK980 PRO on another AJAZZ firmware that Keymotion doesn't know yet gets nothing sent to it; Keymotion offers **Request support** instead.

### The test guide

To help us check firmware 3.01 on real keyboards, Keymotion offers an optional test guide: nine steps, about ten minutes. The **Connection** page offers it for any keyboard on firmware 3.01 on the USB cable; the invitation on the Overview shows only when Keymotion can also write to the keyboard. On firmware 1.06 you never see either. Your answers belong to the firmware they were given on: on another firmware the guide starts afresh.

<Screenshot name="aa-guide-invite" alt="The Overview of a keyboard on firmware 3.01 with the invitation under the keyboard: Could you help us with the new keyboard firmware?, and the Start the test, Not now and Don't show again buttons" />

- **The invitation.** The Overview asks once: **Start the test**, **Not now** (it asks once more the next time you connect the keyboard) or **Don't show again**. It's a strip on the page, not a window: the page works as usual.
- **Where it stays.** **Connection** always shows **Test guide**, with how far you got, and **Open the guide**.
- **The steps.** Getting ready, Connection, Lighting effect, Live lighting, Per-key color, Key mapping, Macros, Screen (optional) and Restore. The guide stays open beside the pages: **Go there** opens the page a step needs. Answer **Worked**, **Didn't work** or **Skipped**, and add a short note if you like; **Next step** asks for an answer first. **Cancel** closes the guide at any step and keeps your progress, also when Keymotion starts again.
- **Checked by Keymotion.** Where Keymotion can tell by itself, a step says so with a check mark: the backup from the first connection exists, the keyboard was read and takes writes, or a save of that kind was read back from the keyboard while the guide was open (whatever saved it). It never claims a check that didn't happen.
- **When Keymotion only reads the keyboard.** If Keymotion writes nothing to the keyboard right now ([why](/keymotion/help/recovery/#when-keymotion-writes-nothing-to-the-keyboard)), the guide says plainly that the steps that save can't work, and offers **Report a problem**.
- **Sending the results.** At the end, the guide shows the exact text that would go: your answers and notes, the app and Windows versions, and what Keymotion read about the keyboard (the same part as in **Report a problem**, never your macros' contents). The text is in English, for the developers. **Copy and open GitHub** puts it on your clipboard and opens the keyboard form with its title and the keyboard model filled in. GitHub doesn't let Keymotion answer the form's question, so the guide tells you which answer to pick; then paste the text into **Keyboard details**. **Copy only** just copies it. Nothing is sent by itself.

<Screenshot name="aa-guide-step" alt="The Lighting page with the test guide open beside it at step 3, Lighting effect: A lighting effect saved to the keyboard was read back from it (Keymotion checked this itself), the Go there button, the Worked, Didn't work and Skipped choices, a note box, and Cancel, Back and Next step" />

The guide itself writes nothing to the keyboard: you save on the pages, as usual. One step, the screen, may replace the keyboard's clock page; choose **Skipped** to keep it.

<Screenshot name="aa-guide-summary" alt="The test guide's last screen, Test finished: the nine steps with their answers, the text to send, and the Copy and open GitHub and Copy only buttons" />

<Aside type="caution" title="Why we don't just switch them on">
These keyboards accept what they are sent without checking it. On an AULA F108 Pro, a screen animation longer than its limit overwrote the keyboard's own menu pictures for good. The limits are different on every model (107, 140, 141 or 255 frames), so a model is added only with its own measured limits.
</Aside>

### How a keyboard moves up this list

1. Someone with the keyboard sends its details with **Request support**, or [the keyboard form](https://github.com/cebersaban44-rgb/keymotion/issues/new?template=keyboard.yml).
2. We describe the model in Keymotion and prepare a test build for it.
3. The tester tries each feature and reports back. Each report is tracked on GitHub with the `keyboard support` label.
4. Once everything has been tried, the model moves to **Tested and working**, with what works in each connection mode.

The status column goes from **Not tested yet** to **Being tested**, then **Works** or **Doesn't work**.

## Look alike, different inside

Some keyboards look like the AK980 PRO or share a name with one on this page, but use another chip or another command family. Keymotion never sends them anything.

| Keyboard | Why it is different |
|---|---|
| AJAZZ AK980 MAX | Another command family |
| AJAZZ AK820 Pro, the version with firmware 1.07 or 1.16 | Another command family |
| AJAZZ AK820 MAX with the web configurator (MAX HE included) | Another command family |
| AJAZZ AK820 Max Plus (SinoWealth version), AK820 (non-Pro), AK992 | Another chip |
| AULA F75, F87, F87 Pro, F99, F99 Pro | Another chip |
| AULA F87S 8K, Nova98; AJAZZ AK680 V2 / MAX | Another command family |
| AJAZZ AKS068 | VIA/QMK keyboard |

Not known yet: AJAZZ AK870 V2, AK820 MAX Ultra, AK870, AK873, AK966 and AULA F99 Max. If you have one, [send its details](https://github.com/cebersaban44-rgb/keymotion/issues/new?template=keyboard.yml) and we'll find out.
