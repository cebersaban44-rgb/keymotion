Keymotion works with the **AJAZZ AK980 PRO**. Many keyboards are built on the same platform: the same kind of chip, the same command set and often the same vendor program, sold under different names. They could come next, but each one is added only after someone has tried it, because the details that keep a keyboard safe differ from model to model.

## Tested and working

<Image src={ak980} alt="AJAZZ AK980 PRO" width={520} />

| Keyboard | USB cable | 2.4 GHz receiver | Bluetooth | Status |
|---|---|---|---|---|
| **AJAZZ AK980 PRO** | Everything | Typing, media keys and the knob | Typing, media keys, the knob and the battery level | <span class="km-status" data-s="works">Works · tested</span> |

Shops sell this keyboard under more than one name. The one Keymotion is tested with came from AJAZZ's own store, listed as "AK980MAX … V2", with **AK980 V2** on the box. Over USB it calls itself "SONiX AK980 PRO", and that's how Keymotion recognizes it. So the **AJAZZ AK980 V2** with the screen works too. Other AK980 versions, for example ones without the screen, may be different inside: Keymotion checks the keyboard when you connect it and sends nothing to a model it doesn't know.

Settings travel over the USB cable; that is how the keyboard is built. [Connecting the keyboard](/keymotion/guide/connecting/) explains the three connections.

## Same platform, not tested yet

These keyboards appear to speak the same command set as the AK980 PRO, according to other open-source projects that measured them on real keyboards. Keymotion doesn't recognise them yet: when you plug one in, it says **This keyboard isn't supported yet** and offers **Request support**. That button copies the keyboard's details (its USB identity, its name and how Windows describes it) without writing anything to the keyboard. Those details are exactly what we need to add it.

Your keyboard isn't in the list? Plug it in anyway: if Keymotion offers **Request support**, [send us its details](https://github.com/cebersaban44-rgb/keymotion/issues/new?template=keyboard.yml).

<Aside type="caution" title="Why we don't just switch them on">
These keyboards accept what they are sent without checking it. On an AULA F108 Pro, a screen animation longer than its limit overwrote the keyboard's own menu pictures for good. The limits are different on every model (107, 140, 141 or 255 frames), so a model is added only with its own measured limits.
</Aside>

### How a keyboard moves up this list

1. Someone with the keyboard sends its details with **Request support**, or [the keyboard form](https://github.com/cebersaban44-rgb/keymotion/issues/new?template=keyboard.yml).
2. We describe the model in Keymotion and prepare a test build for it.
3. The tester tries each feature and reports back. Each report is tracked on GitHub with the `keyboard support` label.
4. Once everything has been tried, the model moves to **Tested and working**, with what works in each connection mode.

The status column goes from **Not tested yet** to **Being tested**, then **Works** or **Doesn't work**.

## Look alike, different inside

Some keyboards look like the AK980 PRO or share a name with one on this page, but use another chip or another command family. Keymotion never sends them anything.

| Keyboard | Why it is different |
|---|---|
| AJAZZ AK980 MAX | Another command family |
| AJAZZ AK820 Pro, the version with firmware 1.07 or 1.16 | Another command family |
| AJAZZ AK820 MAX with the web configurator (MAX HE included) | Another command family |
| AJAZZ AK820 Max Plus (SinoWealth version), AK820 (non-Pro), AK992 | Another chip |
| AULA F75, F87, F87 Pro, F99, F99 Pro | Another chip |
| AULA F87S 8K, Nova98; AJAZZ AK680 V2 / MAX | Another command family |
| AJAZZ AKS068 | VIA/QMK keyboard |

Not known yet: AJAZZ AK870 V2, AK820 MAX Ultra, AK870, AK873, AK966 and AULA F99 Max. If you have one, [send its details](https://github.com/cebersaban44-rgb/keymotion/issues/new?template=keyboard.yml) and we'll find out.
